# 06 UI 设计说明

> 设计依据：doubao-ui-design 工艺规范（console 工作台形态）——「B 端满屏是图就是设计错误；一个数配一个环比；四种状态齐全」。

## 1. 形态定位

`web-console` 工作台/管理后台形态：**亮场** + 左侧深色导航 + 内容区卡片网格。目标不是炫技，而是信息密度、状态完整、操作可达。

## 2. 设计令牌（Tailwind 4 `@theme` 落地）

> **S2-B2 起 Tailwind 升到 4，`tailwind.config.js` 已删除**——令牌全部写在 `src/style.css` 的 `@theme` 块里（v4 是「配置即 CSS」）。
> 颜色/圆角/阴影/字体名不变，所以历史页面零改动。新增令牌请加到 `@theme`，不要再建 config 文件。

### 色板
| 角色 | 取值 | 用途 |
|---|---|---|
| 中性底 | ink-50 `#f8fafc` | 页面背景（不用纯白） |
| 表面 | white / ink-100 `#f1f5f9` | 卡片 / 列背景 |
| 文字 | ink-900→ink-400 | 标题→次要信息层级 |
| **强调色（唯一）** | brand-600 `#0284c7`（sky） | 主按钮、激活态、链接、进度 |
| 语义色 | emerald / amber / rose | 成功 / 警告 / 危险（只做状态，不做装饰） |

**约束**：同一块面积内只允许一个强调色；`#0ea5e9` 系 sky 蓝用于品牌动作，避免大面积极紫/靛蓝。

### 字阶（有断崖，不是“大一点的正文”）
| 用途 | 字号/字重 |
|---|---|
| 页面标题 | 15-16px / semibold |
| 卡片数据主值 | 24px / bold |
| 正文 | 14px / normal |
| 辅助信息 | 11-12px / ink-400 |
| 代码/工具输出 | 12px / mono（JetBrains Mono 等宽） |

### 圆角角色（只有可点的东西才是圆的）
| 角色 | 值 | 用于 |
|---|---|---|
| control | 6px | 按钮、输入框、菜单项 |
| card | 10px | 卡片、弹窗 |
| pill | 9999px | 标签、状态点、头像、进度条 |

### 栅格与留白
- 内容区 `p-5`；卡片内 `p-4/p-5`；列表行 `py-2.5`
- 卡片间距 12-16px；卡片缝隙可小到一线（表格行 `divide-y`）
- 看板列间距 12px，列内卡片 8px

## 3. 组件规范（`src/style.css`）

> v4 踩坑：`@apply` **不再认 `@layer components` 里自定义的类**。被其他类复用的基类
> （`.btn`、`.tag`）必须用 `@utility` 定义，其余单层类仍可放 `@layer components`。

| 组件 | 类 | 状态覆盖 |
|---|---|---|
| 按钮 | `.btn-primary/.btn-ghost/.btn-outline/.btn-danger`（基类 `.btn` 用 `@utility`） | hover / disabled |
| 输入 | `.input` | focus ring 2px brand-500/30 |
| 卡片 | `.card` | shadow-card 1px 弱阴影 |
| 标签 | `.tag/.tag-brand`（基类 `.tag` 用 `@utility`） | 状态色 |
| 菜单 | `.menu-item(.active)` | 激活 = brand-600/20 底 + brand-300 字 |
| 表格 | `.th/.td` | 表头 12px 中灰，行 hover |

### 弹窗统一走 `components/Modal.vue`

```vue
<Modal :show="!!previewing" :title="previewing?.name" width="768px" @close="closePreview">
  ...内容...
</Modal>
```

三个易错点（都踩过）：

1. **用 `:show` 控制显隐，不是 `v-if`**——组件内部自己处理遮罩与过渡，`v-if` 会让关闭动画丢失。
2. **没有 footer slot**——底部按钮直接写在默认插槽里。
3. **`width` 只接受合法 CSS 值**（`768px` / `80%` / `max-w-3xl` ❌）。早期 Files.vue 传了 Tailwind 类名当宽度，浏览器直接忽略，弹窗退化成默认宽度。

## 4. 品牌色与暗色模式（F11 / F22）

### 品牌色：一个变量贯穿全站

| 环节 | 位置 | 作用 |
|---|---|---|
| 写入 | `App.vue` → `document.documentElement.style.setProperty('--brand-color', 用户选的颜色)` | 管理员/个人偏好的品牌色 |
| 读取 | `style.css` 的 `@theme inline` 把 `--color-brand-500/600` 指向 `var(--brand-color)` | 全站 `bg-brand-600`、`focus:ring-brand-500` 自动跟随 |
| 兜底 | 变量未设置时回落到默认 sky 蓝 | 首次进入 / 未登录 |

> 为什么用 `@theme inline`：普通 `@theme` 会在构建期把变量求值成静态色值，运行时改写就不生效了；`inline` 才保留 `var()` 引用。

### 暗色模式：现成的机制，页面适配按需推进

- 声明：`style.css` 顶部 `@custom-variant dark (&:where(.dark, .dark *));`——v4 的 class 策略写法（v3 的 `darkMode: 'class'` 已随 config 一起消失）
- 切换：`Profile.vue` 的 `setTheme()` 往 `<html>` 加/去 `dark` 类，并写 `localStorage`
- 恢复：`App.vue` 启动时读 `localStorage` 立即套用，避免刷新闪白
- 写样式：`class="bg-white text-ink-900 dark:bg-slate-800 dark:text-slate-100"`
- 覆盖现状：机制全通，`CommandPalette` 等组件已适配；**全站逐页暗色化未做**，属独立批次（不是 bug）

## 6. 交互规范

- 行内操作「hover 浮现」（文件列表），保持界面干净
- 拖拽卡片：`cursor-grab` → `active:cursor-grabbing`，落列高亮
- 弹窗统一 `Modal` 组件：遮罩点击关闭 + 顶部标题栏 + 底部操作区
- 全屏 toast 居中底部 2.6s 自动消失，按 type 变色
- 通知红点：未读数 >99 显示 99+
- 页面切换 150ms 淡入；列表行 hover 60ms

## 7. 图标与视觉资产

- 图标用 Unicode/内联字符（树、文件类型、优先级点），不引入图标库依赖，保持 1 个字重风格
- 文件类型用 `fileIcon()` 映射（🖼🎬🎵🗜📄），与 kind 一一对应
- 头像：品牌色底 + 首字（无图时），圆形 `object-cover`

## 8. 响应式

- 布局：侧栏固定 224px，内容弹性；看板横向滚动（`overflow-x-auto`）
- 卡片网格 `grid-cols-2 lg:grid-cols-4`；后台表格 `min-w` + 横向滚动
- 登录页 1024px 以上双栏品牌区，以下单栏表单

## 9. 与 gold 标准的差距说明（诚实披露）

- 未引入真实摄影/插画资产（B 端工作台按规范本身就不以图为主）
- 动效仅保留页面过渡与 hover，未做 signature motion 引擎
- 暗色模式：**机制已具备**（`@custom-variant dark` + `html.dark` 切换 + localStorage 持久化 + 品牌色 `@theme inline`），
  但只有部分组件写了 `dark:` 变体，**全站逐页暗色覆盖仍是待办**（见第 4 节，属独立批次）
