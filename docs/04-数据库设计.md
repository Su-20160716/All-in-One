## 关系要点

- 文件夹/文件/笔记/项目：**归属校验靠 owner 外键**，删除策略 `CASCADE`（文件夹删→子级联）
- 看板成员：Project.members M2M；访问控制 = owner 或 member
- 聊天已读：消息级 `read_by`（JSON 用户 ID 数组）+ 会话级 `UnreadCounter` 计数，两者配合
- 权限链路：Permission.roles → Role.users → User（`has_permission_code`）
- 数据范围：`Role.data_scope`（`self` / `dept` / `dept_and_sub` / `all`）→ `core/scoping.py` 的 `scope_queryset()` 统一收口，多角色取最高权重；`TENANCY_ENABLED` 默认 False 时租户维度短路。

## code 关系要点

- 层级：`CodeWorkspace` 1→N `CodeFile` 1→N `CodeVersion` / `CodeComment` / `CodeShare`；`CodeFile` 1→1 `CodeCollabState`（协同文档，避免多行并发写冲突）。
- 执行记录 `CodeRun` 与文件弱关联（`file` 可为 null，允许脱离工作区直接跑代码）。
- **L5 六张表与原 9 张完全解耦**：每日一题 / 成就 / 错题本 / 学习路径 都只引用 `user`，不反向依赖文件表，删工作区不会连带清空学习数据。
- **L3/L4 接口零新模型**：静态分析、AI 辅助、blame / TODO / diff / 洞察 / 贡献者全部由既有表实时计算得出。
- 唯一约束集中在三处：`CodeVersion.unique(file, version)`、`CodeDailyRecord.unique(user, challenge)`、`CodeUserAchievement.unique(user, achievement)` —— 既防重复，也是三条核心业务链的幂等保证。
