> 口径：**1000 = 34 个业务模块 × 29 项通用能力 + 14 个模块的订阅能力**

## 一、总览

| 指标 | 数值 |
|------|------|
| 业务模块 | 34 |
| 模块分组 | 6（销售与市场、供应链、人力、财务与合规、数据与平台、法务与安全） |
| 通用能力/模块 | 29 |
| 订阅能力 | 14 个模块各 1 项 |
| 功能总数 | **1000** |
| 前端页面 | 34 个业务工作台 + 1 个业务中心目录页 |
| 后端 API 前缀 | `/api/biz/` |
| 数据模型 | `BizRecord` / `BizComment` / `BizActivity` / `BizSavedView` / `BizSubscription` |

**为什么不是 34 套独立表**：34 个业务域共享固定列（标题、状态、分类、优先级、负责人、到期日、标签、归档、软删除）+ `data` JSON 扩展字段，模块差异由 `modules.py` 的字段/状态/分类 schema 驱动。这样新增业务模块只需要加配置，不需要迁移，并且 CRUD、权限、批量、导入导出、统计与审计全部复用同一套经过冒烟验证的引擎。

## 五、权限与数据范围

- 读：`core.scoping.scope_queryset`，按 owner / 部门 / 部门及下级 / 全组织数据范围过滤。
- 写：记录创建人、负责人，或处于可见写范围内的用户；管理员（`superuser` / `staff`）不受范围限制。
- 越权：跨范围读返回 404（不泄露存在性），越权写返回 403；冒烟测试对普通用户与管理员分别验证。
- 审计：写操作经 `OperationLogMiddleware` 自动留痕；记录级动作另写 `BizActivity`，评论写 `BizComment`。
- 订阅：仅本人可读写自己的订阅，管理员可查看汇总。

## 八、行为变更与兼容说明

1. **新增应用**：`bizhub` 已加入 `INSTALLED_APPS`，路由挂载 `/api/biz/`；迁移 `bizhub.0001_initial` 已应用。
2. **统一响应**：所有业务接口返回 `{ok:true,data}`，异常由 `devtools.common.endpoint` 兜底为 `{ok:false,error}`。
3. **CSV 导出参数**：使用 `fmt=csv`，避免 DRF `URL_FORMAT_OVERRIDE` 把 `format` 当作内容协商参数。
4. **软删除与归档分离**：回收站只显示 `is_deleted`，归档列表只显示 `archived`；恢复与取消归档互不影响。
5. **订阅去重**：同一用户同一天只推送一次；`bizhub_digest --dry-run` 不写 `last_sent_at`。
6. **优先级枚举**：bizhub 使用 `low/normal/high/urgent`；项目看板继续使用 `low/medium/high/urgent`，两者互不影响。
7. **侧边栏**：新增“业务中心”入口 `/biz`；34 个业务页面通过 `/biz/<slug>` 直达，侧边栏按 `/biz` 前缀高亮。
8. **无假数据**：业务中心目录页和 34 个工作台只展示接口返回的真实记录，加载失败时降级提示并允许重试。
9. **CSV 公式注入防护**：导出时对以 `=`、`+`、`-`、`@`、制表符或回车开头的单元格前置 `'`，防止 Excel 把用户输入当公式执行。
10. **导入上限**：单次最多 500 行，逐行校验并返回错误行号；批量操作单次最多 200 条。
