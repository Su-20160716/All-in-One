**统一约束（所有 59 项共同遵守）**

1. 新增接口一律挂在 `/api/<app>/` 下，不改动既有路由；`code/urls.py::_EXPECTED`、`minitools/urls.py == 375` 两条契约断言只增计数，不改旧值。
2. 新增模型字段一律 `null=True` 或带 `default`，迁移可前滚；不改既有字段的 `null`/`blank` 语义。
3. 外部依赖（LLM、LibreOffice、汇率 API 等）一律走 `core/adapters.py`，缺失时必须降级而不是 500。
4. 前端新页面复用 `card / input / btn-* / tag / th / td` 与 `brand-*` / `ink-*` 令牌；弹窗用 `components/Modal.vue`；提示走 `useAppStore().toastMsg()`；错误文案一律 `e?.message`。
5. 列表接口默认接 `StandardPagination`（`core/pagination.py`），且查询必须 `select_related / prefetch_related` 到位。

## 一、core · 全局能力（5 项）

### F01 操作日志检索与前后值对比

- **作用**：管理员可按模块/操作人/时间/关键词检索 `OperationLog`，并对「更新」类操作展示字段级前后对比（当前只存一行摘要）。
- **实现要点**：新增 `GET /api/core/logs/search/`（复用 `StandardPagination`）；模型加 `diff` JSONField（`null=True`）；在 `core/middleware.py` 记录前取一次 `model_to_dict`（仅对 PATCH/PUT 且路径命中已注册模型时启用），落库到 `diff`。前端 `views/admin/Logs.vue` 加对比抽屉。
- **影响**：`core/models.py` 加 1 字段 + 1 迁移；中间件多一次序列化（可用 `SAMPLE_MODELS` 白名单限定在 notes/files/projects 三类，避免全局开销）。
- **兼容性**：老日志 `diff` 为 `null`，前端按"无对比"降级展示；`SKIP_PREFIXES` 逻辑不变。

### F02 系统健康巡检面板

- **作用**：一屏看 DB 连接/查询耗时、MEDIA 磁盘占用、慢接口 TOP10、WS 在线连接数、后台任务积压。
- **实现要点**：`GET /api/core/health/` 聚合：`connection.ensure_connection()` + `SELECT 1` 计时、`shutil.disk_usage(MEDIA_ROOT)`、复用已有 `SlowEndpoint` 模型取 TOP、`get_channel_layer()` 计数（Redis 时用 `llen`）。前端新增 `views/admin/Health.vue`。
- **影响**：新增 1 视图 + 1 页面 + 1 路由；只读，无迁移。
- **兼容性**：纯新增；无 Redis 时 WS 计数降级为 `null` 并标注"当前使用内存 channel layer"。

### F03 通用导入导出框架

- **作用**：任意模块的列表可导出 CSV/JSON，也可按模板导入，带字段映射预览与错误行回执。
- **实现要点**：`core/importer.py` 提供 `export_rows(qs, fields, fmt)` 与 `import_rows(file, mapping, model)`；统一响应头用 `filename*=UTF-8''`（顺带修掉 `core/views.py:672` 的头部注入）。各模块只需声明 `EXPORT_FIELDS`。
- **影响**：新增 1 个工具模块 + `GET/POST /api/core/io/<app>/` 两个通用端点；不触碰各 app 既有导入实现。
- **兼容性**：与 `files` 现有"收藏导入"并存，后者保持原样，可后续迁移。

### F04 通知中心增强：分渠道 + 免打扰

- **作用**：通知可走站内/邮件/Webhook 三种渠道；用户可设免打扰时段与按类别静音。
- **实现要点**：`core/notify.py` 抽出 `dispatch(user, title, content, channels=[...])`，内部复用既有 `notify()`；新增 `NotificationPreference` 模型（user, category, channel, muted, quiet_start, quiet_end）；邮件走 `django.core.mail`，Webhook 走 `requests` 且失败只记日志。群发改 `bulk_create`（顺带修 `core/views.py:1329` 的逐条 INSERT）。
- **影响**：新增 1 模型 + 1 迁移 + 1 设置页；既有 `notify()` 签名不变。
- **兼容性**：老调用点无需改动；未配置邮件时自动只发站内。

### F05 统一附件引用与孤儿清理

- **作用**：跨模块（笔记/卡片/消息/工单）统一用 `file_id` 引用文件；定期清扫无引用且超期的物理文件。
- **实现要点**：`core/attachments.py` 提供 `link(owner_obj, file_ids)` / `unlink` / `referenced_ids()`；新增管理命令 `manage.py gc_media --dry-run`，扫描 `FileMeta` 中 `is_deleted=True` 且超 30 天且无引用的记录，按引用计数删物理文件（顺带修 `files/views.py:1285` 的缩略图共享删除 bug）。
- **影响**：新增 1 工具模块 + 1 命令；不动既有 `FileMeta` 字段。
- **兼容性**：`gc_media` 默认 `--dry-run`，必须显式 `--apply` 才删；不改变现有上传流程。

## 二、accounts · 账号与权限（5 项）

### F06 登录设备管理

- **作用**：用户可查看自己在哪些设备/IP 登录、最后活跃时间，并一键踢出指定设备。
- **实现要点**：复用已有 `ActiveSession` 模型；新增 `GET /api/auth/sessions/`、`DELETE /api/auth/sessions/<id>/`（踢出即 `token_version` 不变，仅删会话记录 + 前端强刷）；前端 `views/Profile.vue` 加"登录设备"卡片。
- **影响**：新增 2 个端点 + 1 个卡片；`token_version` 语义不变。
- **兼容性**：与既有 B12"改密踢全设备"互补；踢单设备不触发全端重登。

### F07 双因素认证（TOTP）完整流程

- **作用**：用户可启用动态口令二次验证，含二维码绑定、恢复码、关闭校验。
- **实现要点**：`accounts/totp.py` 已有常量时间比较与 ±1 窗口，补：`POST /api/auth/2fa/enable/`（返回 `otpauth://` 与二维码 SVG）、`/verify/`、`/disable/`（要求密码 + 当前码）、`/recovery/`（一次性恢复码，存哈希）。登录流程在 `MyTokenObtainPairSerializer` 增加可选 `otp` 字段（不传且用户已启用 → 返回 `need_2fa` 标记）。
- **影响**：新增 4 端点 + `User` 加 `totp_secret / totp_enabled / recovery_codes`（`null=True`）+ 1 迁移。
- **兼容性**：**默认关闭**，未启用用户登录流程完全不变；已启用才校验 `otp`。

### F08 组织架构树可视化编辑

- **作用**：拖拽调整部门层级、增删改部门与负责人，实时显示人数与层级路径。
- **实现要点**：复用 `Department` 的 `path_name()` / `descendant_ids()`；新增 `PATCH /api/auth/departments/<id>/move/`（入参 `parent_id`，落库前用 `descendant_ids()` 校验不形成环）；前端 `views/admin/Departments.vue` 用纯 CSS 缩进树 + 拖拽落点高亮。
- **影响**：新增 1 端点 + 1 页面；`Department` 模型不变。
- **兼容性**：移动校验复用既有环检测思路（参考 `notes._would_create_cycle`），不影响既有查询。

### F09 用户活跃热力图

- **作用**：按周×小时展示用户/团队活跃分布，用于评估协作节奏。
- **实现要点**：`GET /api/auth/activity-heatmap/?days=90`，用 `TruncHour`/`TruncDate` 聚合 `LoginLog` 与 `OperationLog`；前端 SVG 热力图（不引图表库，与 `AdminStats.vue` 风格一致）。
- **影响**：新增 1 端点 + 1 组件；只读。
- **兼容性**：纯新增；数据量大时按 `days` 上限 180 截断。

### F10 权限矩阵可视化

- **作用**：角色 × 权限以矩阵呈现，勾选即生效，支持复制角色。
- **实现要点**：复用 `Role` / `Permission` 的多对多；新增 `GET /api/auth/roles/<id>/matrix/`、`PUT /api/auth/roles/<id>/matrix/`（批量 `set()`，事务包裹）；前端矩阵表用 `th/td` 类。
- **影响**：新增 2 端点 + 1 页面；`Role` 结构不变。
- **兼容性**：与既有角色编辑接口并存，二者写同一张关联表，幂等。

## 三、files · 文件与存储（5 项）

### F11 文件版本历史

- **作用**：覆盖上传或在线编辑时保留历史版本，可预览/下载/回滚任意版本。
- **实现要点**：新增 `FileVersion` 模型（file FK, version, storage_path, size, sha1, created_by, created_at）；在 `FileMeta.save` 之外的写路径（`UploadCompleteView`、`FileSaveTextView`）追加版本记录；`GET /api/files/<id>/versions/`、`POST /api/files/<id>/versions/<v>/restore/`。顺带修掉"秒传共享物理文件被覆盖"的 bug（写前脱链）。
- **影响**：新增 1 模型 + 1 迁移 + 3 端点；`FileMeta` 字段不变。
- **兼容性**：历史文件默认无版本记录，列表显示"仅当前版本"；`FILE_VERSION_KEEP` 默认保留 5 个，可环境变量配置。

### F12 全文检索增强（文件名 + 内容 + 标签）

- **作用**：一次搜索同时命中文件名、正文（文本类文件）、标签，结果按 BM25 排序。
- **实现要点**：复用 `core/search.py` 的 BM25 与 `SearchDoc.module`（已支持 `code`/`snippet`）；在文件上传/编辑后写入 `SearchDoc`（`module="file"`），文本类文件抽取前 64KB；`GET /api/files/search/?q=`。
- **影响**：新增 1 端点 + 1 个索引写入钩子；`SearchDoc` 结构已支持。
- **兼容性**：与全局搜索并存；未索引的老文件回退到 `name__icontains`。

### F13 存储配额预警与清理建议

- **作用**：接近配额时提示，并给出「最大文件 / 最久未访问 / 重复文件」三类清理建议。
- **实现要点**：`GET /api/files/quota/advice/`，聚合 `size` TOP、`last_access_at` 最旧、按 `sha1` 分组找重复；前端在 `views/files/Analysis.vue` 加一块建议卡片。
- **影响**：新增 1 端点 + 1 卡片；只读。
- **兼容性**：纯新增；建议项只做跳转，不自动删除。

### F14 分享链接访问分析

- **作用**：查看分享被访问的次数、最近访问时间、独立访客数（IP 哈希去重）。
- **实现要点**：新增 `ShareVisit` 模型（link FK, ip_hash, ua_hash, created_at）；在 `validate_link` 通过处记一条；`GET /api/files/shares/<id>/analytics/`。
- **影响**：新增 1 模型 + 1 迁移 + 1 端点；`ShareLink` 字段不变。
- **兼容性**：老分享无历史访问数据，从上线起统计；`max_downloads` 逻辑不变。

### F15 批量重命名规则引擎
