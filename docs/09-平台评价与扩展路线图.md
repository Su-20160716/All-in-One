# 全能协作平台 · 完整评价与 100 项功能扩展路线图

> 文档性质：**诊断 + 规划**。不是功能清单，是「这个项目现在是什么、值多少、下一步该往哪走」的判断书。
> 撰写依据：对 `backend/` 16 个 app（约 7.2 万行 Python、145 个模型）、`frontend/src/views` 41 个页面、docs 全篇与 `FEATURES.md` 全量账本的实读（规模数字按 2026-10-24 `scripts/stats.py` 复核）。

## 第一部分 · 完整评价

### 1.2 真正值得夸的地方（五条）

**① 工程纪律强得反常。**
个人项目普遍"能跑就行"，而这个项目有：路由契约断言（`code/urls.py` 的 `_EXPECTED = 110`、`minitools/urls.py` 的 `== 375`，防止接口被无声删改）、五套冒烟测试串行回归（还专门记录了"并行会撞 SQLite database is locked"）、行级权限统一收口 `core/scoping.py`（业务模型零冗余字段）、"只增不改"的版本兼容原则、统一异常链（ValueError→400 / 其余→422，绝不 500）。
> **这套纪律的成熟度超过很多小公司的在产项目。这是你最大的隐性资产。**

**② 可降级适配器是架构级亮点。**
外部依赖缺失一律不 500：无 `LLM_API_KEY` → AI 全走本地实现（且本地实现是"真能用"的抽取式摘要/启发式评分，不是占位符）；无 LibreOffice → 结构化 `LIBREOFFICE_NOT_FOUND` + 安装引导；无语言运行时 → `RUNTIME_NOT_FOUND` + 前端置灰。
> **这条设计让项目"在任何环境下都能完整演示"，是实用主义的胜利，也是最该推广到全项目的模式。**

**③ 代码工坊（v6）是全项目唯一具备"产品感"的模块。**
15 张表 / 104 登录接口 + 2 公开接口 / CodeMirror 5 个 Compartment 独立热切换 / 判题核心 `run_judge()` 抽成纯函数被「普通判题 + 每日一题 + 竞技场」三处复用（杜绝逻辑分叉）/ 成就系统惰性结算（不引入定时任务）/ 公开分享通道权限收得更严（超时压到 10s、不落库防刷）。
> **这里有真正的架构思考，是全项目技术含金量最高的部分。**

**④ 文档体系完整。**
8 篇 docs（需求/架构/API/DB/部署/UI/免费云/ClawCloud）+ `FEATURES.md` 版本总账，且"模块记账口径"分版本独立（v3/v4/v5/v6 不并入主平台总数）—— 这种"可横向对比版本体量"的习惯，是长期维护者才有的意识。

**⑤ 权限模型分层设计正确。**
RBAC（权限点→角色→用户）+ 叠加行级数据范围（self / dept / dept_and_sub / all，多角色取最高权重）+ 可选多租户（`TENANCY_ENABLED` 默认 False 保证向后兼容）。隔离链"租户 → 用户集合 → 数据范围"清晰，且不污染业务表结构。

### 1.3 必须直面的问题（七条）

**① 定位灾难级模糊 —— 这是最致命的问题。**
平台里同时住着：文件网盘、笔记知识库、看板、IM、RBAC 后台、10 种编程语言教学、K12 化学方程式配平、古诗接句默写、报销审批、会议室预订、固定资产、访客登记、快递代收、用印、值班排班、OKR、工单……
一个真实用户需要"能配平化学方程式又能提交报销单"的系统吗？**答案是：没有。** 目前唯一的真实用户就是作者本人。这导致：没有用户画像 → 没有优先级依据 → 只能靠"再加一个模块"来推进，形成功能膨胀的惯性。

**② 一半体量由静态数据撑起，不是"能力"而是"内容"。**
learning 模块 15,000 行里绝大部分是硬编码字典：118 个化学元素、457 个知识点、70 条成语、181 个汉字、52 条方程式、139 个英语单词、30 首古诗、115 道题……
> 问题在于：**内容会腐烂**（教材改版、知识点更新），而内容维护是人力密集型工作。一个人维护不动，且这些内容对"技术能力展示"的边际贡献趋近于零。

**③ 巨型组件是定时炸弹。**
`CodeForge.vue` 85.4 KB 单文件（约 1700+ 行）承担了三栏布局 + 编辑器 + 执行 + AI + TODO 面板 + 洞察面板 + 行评论 + 协同 + 分享 + 导出 + 片段库。改任何一处都要通读全文，且无法被单元测试覆盖。

**④ 运行时行为缺少自动化验证。**
`FEATURES.md` 10.9 自述："`manage.py test code` / 端到端在开发机上被安全策略拦截，运行时行为改由人工验收"。意味着**沙箱执行、判题、文件合并**这些最容易出事、最需要回归的路径，目前靠手点。

**⑤ AI 是"外挂"而非"内核"。**
LLM 只在 `assistant` 和 `code` 两个 app 里被调用。其余 800+ 接口与 AI 零关系 —— 搜索不懂语义、笔记不会自动关联、看板不会预测风险、文件不会自动归档。2026 年做一个知识/协作平台而不把 AI 嵌进核心流程，等于主动放弃最大杠杆。

**⑥ "接口数量"是虚荣指标。**
1518 条接口中，模板化 CRUD（`list/`、`create/`、`detail/`、`update/`、`delete/`）占比极高。多 ≠ 好：更多攻击面、更多一致性风险、更多维护成本、更长的审计时间。**应该统计的是"有多少个接口真正形成了闭环工作流"，而不是"有多少个接口"。**

**⑦ 从未真正为"被别人使用"做过准备。**
多租户默认关闭、Redis 可选、无环境隔离（dev/prod 配置靠环境变量凑）、无 API 限流、无审计合规、无数据备份策略。整套系统的隐含假设是"单机单用户演示"。

### 1.4 一句话定位诊断

> **这不是"全能协作平台"，而是一个用 6 个版本堆出来的「全栈技术能力展示柜」+「个人数字工作台」。**
>
> 它当前的真实价值排序是：
> 1. **作为能力证明**（技术广度、架构纪律、全栈能力）—— 价值最高，已超标；
> 2. **作为个人自用工作台**（笔记/文件/看板已够用）—— 价值中等，但被冗余模块拖累；
> 3. **作为对外产品** —— 价值当前接近于零，需要先做减法而非加法。

**给三个不同目标的路线建议：**

| 目标 | 该做的事 |
|---|---|
| **求职 / 作品集** | 停止加功能。挑 **1 个模块**（推荐代码工坊）做深做到"可演示 + 有测试 + 有数据"，其余模块降级为"技术广度佐证"。写清楚架构决策文档。 |
| **个人长期自用** | 砍掉 officesuite / learning 中自己永远不用的部分，把节省的精力投入 AI 内嵌与搜索质量。**做减法。** |
| **真的对外发布** | 重新选一个垂直场景（如"团队代码评审与教学平台"），围绕它重构信息架构，其余模块摘掉。**先做 MVP，而不是先做全量。** |

## 第二部分 · 100 项功能扩展清单

> 分层原则：**A 类（架构修复，必做）→ B 类（AI 内嵌，最高性价比）→ C 类（体验补全）→ D 类（垂直深耕）→ E 类（炫技/展示用）**。
> 每项标注：做什么 + 为什么值得做 + 落地成本（低/中/高）。

## 第三部分 · 如果只做 5 件事

如果精力有限，按此顺序：

1. **拆巨型组件 + 补沙箱自动化测试**（#1 #2）—— 保住现有资产不腐烂。
2. **AI 语义搜索 + 自然语言查询**（#21 #25）—— 用最小代价让 870 个接口"有了统一入口"，性价比最高。
3. **文件存储适配层**（#8）—— 解锁云部署的最后一道锁。
4. **砍掉一半不用的模块**（不是新增，是删除）—— 唯一能让这个项目从"展示柜"变成"产品"的动作。
5. **给平台写一句真正的定位**—— 一句话说不清"给谁用、解决什么问题"的项目，加 100 个功能也不会变清晰。
