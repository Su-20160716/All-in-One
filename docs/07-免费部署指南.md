# 07 · 免费云部署指南（Cloudflare Pages + Render + Neon）

> ## ⚠️ 本方案已被 docs/08 取代（2026-09-14 定案）
> Render 与 Neon 在国内均不可直连（实测），日常访问会卡在登录页。**现行方案是
> [docs/08-ClawCloud部署教程.md](08-ClawCloud部署教程.md)**：ClawCloud Run 新加坡区 + CF Pages + SQLite 持久卷。
> 本文仅作历史方案留档；里面的部署步骤仍正确，只是**国内不推荐**。

> 架构：前端（Vue3 静态站）→ Cloudflare Pages（全球 CDN，免费）
> 后端（Django 5 + Daphne/ASGI）→ Render 免费档（支持 WebSocket）
> 数据库 → Neon 免费 PostgreSQL（云端持久化，数据不随重启丢失）

---

## 0. 免费额度与限制（先知道丑话）

| 服务 | 免费额度 | 关键限制 |
|---|---|---|
| Cloudflare Pages | 无限带宽、500 次/月构建 | 需要构建环境（自动 npm install） |
| Render | 750 小时/月 实例 | **闲置 15 分钟休眠，冷启动约 1 分钟**；磁盘临时（上传文件会丢） |
| Neon | 0.5 GB 存储 | 闲置自动暂停计算（首次连接慢几秒） |

**本方案下保得住的**：数据库全部内容（账号/消息/笔记/任务等）✅、WebSocket 实时功能 ✅
**保不住的**：上传的文件（media）——Render 磁盘临时，重部署/重启即丢 ❌（R2 迁移见文末二期）

---

## 1. 准备：创建 Neon 数据库（5 分钟）

1. 注册 https://neon.com（可 GitHub 登录）
2. 新建 Project（区域选 Singapore/AWS 最近的）
3. Dashboard 里找到 **Connection string**，复制形如：
   ```
   postgres://user:pass@ep-xxxx-pooler.region.aws.neon.tech/neondb?sslmode=require
   ```
4. 留着备用（Render 配置时粘贴）

> 建议选 **pooled connection**（连接串带 `-pooler`），免费档连接数更宽裕。

## 2. 部署后端到 Render（10 分钟）

> **说明**：仓库里**没有** `render.yaml`（早期确实写过一版，后来弃用了，避免仓库出现两套互相打脸的部署配置）。
> 所以只有「方式 B 手动建服务」这一条路，按下面的表格逐项填即可。如果你确实想用 Blueprint，
> 需要在仓库根新建 `render.yaml`，字段照方式 B 的配置填（`rootDir: backend`、`dockerfilePath` 略、`healthCheckPath: /api/core/health/`）。

**方式 B（手动建服务）**：New → Web Service，按以下配置：

| 配置项 | 值 |
|---|---|
| Root Directory | `backend` |
| Runtime | Python 3.13 |
| Build Command | `pip install -r requirements.lock && python manage.py collectstatic --noinput && python manage.py migrate` |
| Start Command | `daphne -b 0.0.0.0 -p $PORT config.asgi:application` |
| Health Check Path | `/api/core/health/` |

**环境变量（Environment 标签页）：**

| 变量 | 值 | 说明 |
|---|---|---|
| `DJANGO_SECRET_KEY` | 点 Generate | |
| `DJANGO_DEBUG` | `0` | 生产必填 |
| `DJANGO_ALLOWED_HOSTS` | `.onrender.com` | |
| `DATABASE_URL` | 第 1 步的 Neon 连接串 | 数据落 Neon；**不填则退回 SQLite，警告见下** |
| `CORS_ALLOWED_ORIGINS` | `https://你的前端.pages.dev` | 第 3 步部署完回填 |
| `CSRF_TRUSTED_ORIGINS` | 前端地址 **和后端自己**，如 `https://xxx.pages.dev,https://coop-platform-backend.onrender.com` | 后端那个是给 `/admin` 登录用的，漏了会被 CSRF 拦截 |
| `LLM_API_KEY` | 可选 | 不填则 AI 自动降级本地实现 |

创建后你会得到后端地址，形如 `https://coop-platform-backend.onrender.com`。

> **⚠️ SQLite 模式的代价（务必看清）**：Render 免费档闲置 15 分钟会休眠，**唤醒 = 全新容器**——SQLite 文件和 media 目录直接清空。也就是说不用等重部署，只要晚上没人访问，第二天早上昨晚注册的账号、发的消息就蒸发了。SQLite 模式只适合"跑通流程、看看效果"；要真用，随时把 Supabase/Neon 的连接串填进 `DATABASE_URL` 保存，实例重启即完成切换，代码零改动。

> 首次部署会自动 `migrate` 建表。默认无账号：先临时用 Render Shell（Dashboard → Shell）执行
> `python manage.py createsuperuser` 建管理员。

## 3. 部署前端到 Cloudflare Pages（10 分钟）

1. Cloudflare Dashboard → **Workers & Pages → Create → Pages → Connect to Git**
2. 选中本仓库，配置：

| 配置项 | 值 |
|---|---|
| Root Directory | `frontend` |
| Build Command | `npm run build` |
| Build Output Directory | `dist` |

3. **环境变量（Settings → Environment variables，Production 和 Preview 都加）：**

| 变量 | 值 |
|---|---|
| `VITE_API_BASE` | `https://coop-platform-backend.onrender.com`（第 2 步的后端地址） |
| `NODE_VERSION` | `22` |

4. 部署完成后得到 `https://xxx.pages.dev`。
5. **回填**：把该地址加进 Render 的 `CORS_ALLOWED_ORIGINS`；`CSRF_TRUSTED_ORIGINS` 要加**两个**（前端地址 + 后端自己的 `https://coop-platform-backend.onrender.com`），保存后 Render 会自动重新部署。

### 原理说明（为什么改了前端代码）

- 前端原来全靠 Vite 代理的相对路径（`/api`、`/media`、`/ws`）。上了 Pages 后同域没有后端，所以新增了 `src/api/base.js`：
  - 不设 `VITE_API_BASE` 时行为与原来完全一致（本地开发零变化）；
  - 设置后，axios 基地址、token 刷新请求、WebSocket 地址（自动转 wss）全部指向后端；
  - 响应拦截器统一把后端返回的 `/media/...`、`/share/...` 相对路径补全成后端绝对地址。
- `frontend/public/_redirects`：SPA history 路由刷新回退（`/* /index.html 200`）。

## 5. 冷启动缓解（可选但强烈建议）

Render 免费档闲置 15 分钟休眠，同事早上第一个进来要等约 1 分钟。用 **UptimeRobot**（免费）：

1. 注册 https://uptimerobot.com → Add New Monitor
2. 类型 HTTP(s)，URL 填 `https://coop-platform-backend.onrender.com/api/core/health/`，间隔 5 分钟

有心跳就基本不休眠（750 小时/月免费额度 = 全月在线，够用）。

## 5.5 进阶：自定义域名（有 CF 付费账户/自有域名时）

Django 代码**零修改**。给后端套自己的域名（如 `api.example.com`），只需改 Render 上 3 个环境变量的值：

| 变量 | 改成 |
|---|---|
| `DJANGO_ALLOWED_HOSTS` | `.onrender.com,api.example.com` |
| `CORS_ALLOWED_ORIGINS` | `https://www.example.com`（前端的自定义域名） |
| `CSRF_TRUSTED_ORIGINS` | `https://www.example.com,https://api.example.com` |

前端同理：CF Pages 的 Custom domains 绑定 `www.example.com`，`VITE_API_BASE` 改成 `https://api.example.com` 后**重新触发一次构建**（构建时变量才生效）。

注意事项：

- **CF 代理（橙色云）可以开**：CF 支持 WebSocket 转发，IM 不受影响；`SECURE_PROXY_SSL_HEADER` 已在代码里配好，自动识别 CF 传来的 HTTPS 头。
- **CF 代理不能防休眠**：Render 实例闲置照样睡，没人访问时 CF 也唤不醒（没人请求它）。UptimeRobot 方案照旧保留。
- **别想把 Django 塞进 CF Workers**：Workers Paid 的 Python 支持跑不了 Daphne + Channels + 本地磁盘文件这套组合，Django 继续住 Render，别折腾。

## 6. 已知限制

- **上传文件不持久**：Render 免费档没有持久磁盘，重部署后 media 目录清空（头像、附件、缩略图）。数据库里的记录还在，但文件本体丢失。→ **现行方案（docs/08）用 `DATA_DIR` 把 SQLite + media 一起放到持久卷，重启不丢**；Render 若要用需付费挂 Disk 并在 `DATA_DIR` 指向它。
- **LibreOffice 不可用**：Render 容器装不了 soffice，「转 PDF」接口会按既有约定返回结构化提示（`LIBREOFFICE_NOT_FOUND`），不会 500。
- **AI 助手**：`LLM_API_KEY` 可配任意 OpenAI 兼容服务（如 NVIDIA NIM），不配则本地降级实现。
- **全文搜索/文档抽取**：纯 Python 实现，云上正常工作。

## 7. 二期：文件迁 Cloudflare R2（暂未实施）

R2 免费 10GB，适合存 media。但当前文件模块直接操作本地磁盘（分片上传落盘、缩略图生成、转 PDF、正文抽取全部 `open()` 本地路径），直接把存储后端换成 S3 会导致这些功能静默坏掉。正确姿势是把「磁盘读写」收口成存储适配层（本地 / R2 双实现，按 `STORAGE_BACKEND` 切换，沿用可降级约定），属于一次小型重构，建议单独立项。
